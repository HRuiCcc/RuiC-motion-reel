# 坑：这些全是真踩过的

每一条都花了时间才找出来，而且症状都不指向真因。写在这里省下一次重踩。

## 引擎

1. **PIL 的字形包围盒是相对 ascender，不是基线。**
   `font.getbbox("H")` 返回的 y 是相对**上伸线**的，而绘制时的锚点 `'ls'` 是**基线**。
   按字高居中/对齐必须减掉 `ascent`，否则**整段文字低一个字身**（168px 字号偏 147px）。
   实测验证法：把 "H" 画在 y=400，量墨迹上边，看是不是 `400 + bbox_top - ascent`。

2. **PIL 既不抗锯齿也不做混合。**
   `ImageDraw` 在 RGBA 上是**替换**像素不是 source-over，画多边形也没有 AA。
   做法：每个图元先画成不透明的覆盖率遮罩，整体 `alpha_composite`，
   抗锯齿**来自提交时的降采样**（2× 超采样 → box 降采样）。

3. **`down2()` 写死 2× 降采样**，所以 `Canvas(ss=1)` 会让 `commit()` 崩（形状不匹配）。
   改 `commit` 时记得判断 `ss`。

4. **`_clear()` 只清上一个图元的包围盒**（性能优化）。
   新图元若写到更宽的范围，必须自己保证那块是干净的。

5. **`ImageFilter.MinFilter` 很贵。** 在 2560×1440 全画幅上跑 13×13 会到秒级。
   描边文字必须**先裁到字形包围盒**再做腐蚀。

6. **点云采样密度不足会在掠射角与网点打架，出摩尔纹。**
   症状是亮部出现细密的波纹（不是噪点）。
   药：密度加倍 + `render(soften=1)`（对覆盖率与亮度做亚像素模糊）。

7. **零厚度曲面侧视会碎成尖刺。** 带子转到与镜头平行时投影宽度趋零，相邻采样点散开。
   药：用 `sweep_ellipse` 扫一个**扁椭圆截面**（有厚度、闭合），不退化了。

8. **超形（Gielis）在尖刺参数下自交**，且细瓣会走样成点线。
   当花饰用就换成温和形体；非要尖刺就把 `n1` 调大、并把采样密度提上去。

## 数值

9. **分数次幂遇到负数会产生 NaN。**
   `(1.0 - e) ** 1.35`，而 `e` 因为过冲项会超过 1 → NaN 污染整条粒子位置。
   带过冲的缓动后面接幂运算，**先 `np.clip(x, 0, None)`**。

10. **`np.where` 不短路。** `np.where(mask, x**0.45, 0.0)` 仍会算 `x**0.45`（负数→NaN→警告）。
    先 clip。

11. **粒子"重生"写进了容器又被下一行覆盖。**
    ```python
    self._respawn(n)                 # 写进 self.pos[bad]
    self.pos = np.stack([x, y], -1)   # ← 覆盖掉了
    ```
    症状：粒子飘出画幅后**再也不回来**，画面在中途变空。这类"状态被覆盖"的 bug
    在长时间轴里才显形，单帧预览看不出来。

## 音频

12. **重叠相加滤波要除以窗和，不是窗平方和。**
    窗只加了一次（分析侧），除以 `Σwin²` 会引入 2× 纹波；
    而首尾样本处 `Σwin→0`，用 `max(…, 1e-6)` 兜底会把舍入噪声**放大上千倍**。
    正确写法：`out / where(wsum > 2e-3, wsum, 1.0)`，两侧直接输出 0。

13. **归一化顺序**：先软限幅 → 再首尾淡入淡出 → **最后**归一化。
    反了的话开头瞬态决定天花板，整首偏轻。

14. **AAC 编码后采样间峰值会超过采样峰值**（实测 +0.3~+1.0 dB）。
    采样峰值定 0.92 会得到 +0.3 dBTP（已超 0）；定 **0.82~0.86** 才安全。

## 管线与观感

15. **输出不要做第二次 sRGB 编码。**
    颜色从 `#05080D` 这种值开始就是显示值，输出时再"线性→sRGB"会把**所有暗部抬亮约 2.5 倍**，
    表现为"怎么调都发灰"。判据：对着参考片量中位数，差 2 倍以上先查这里。

16. **bloom 权重过大会把光铺满全画幅。**
    权重 0.5+0.42+0.3 的大半径八度会让背景整片抬起来。
    合理起点：`octaves=((2,4,0.30),(4,6,0.20),(8,5,0.11))`，阈值 0.68~0.70。

17. **亮场上的暗字会被 bloom 冲灰。** 见 `print-pipeline.md` 第九节。
    同理，"亮场"要用乘法压亮，不要加色。

18. **切点爆闪必须在暗角之后叠加**，否则四角发灰、爆闪变成灰雾；
    3D 场/大面积亮场要把爆闪强度降到 0.4，不然整帧洗白。

19. **采样 logo 剪影要用 alpha 通道，不是亮度。**
    `convert("L")` 取的是辉度：上亮下暗的标识会**只活下来亮的那半边**，
    粒子只拼出左上角一块。用 `getchannel("A")`。

20. **`ui(size, weight)` 这类按权重查表的函数要做最近邻吸附**，
    传了表里没有的权重（600）会直接 KeyError。

## 文案

21. **要求全英文/不要某品牌时，渲完要扫一遍源码字符串**，不要靠记忆：
    ```bash
    python3 -c "
    import re,pathlib
    s=''.join(pathlib.Path(p).read_text() for p in pathlib.Path('.').rglob('*.py'))
    print(re.findall(r'[\u4e00-\u9fff]+', s) or 'no CJK')"
    ```
    注释里残留的旧品牌名同样要清（交付时容易被看到）。

# 第二批（2026-09-28，做第四条视觉语言「银盐 / 暗房」时踩的）

## 引擎 / 管线

22. **切点爆闪写成 `exp(-max(0, tl - t0) / k)`，会把 t0 之前的整段洗白。**
    `tl < t0` 时 `max` 恒为 0 → `exp(0) = 1` → 爆闪在 **t0 之前就已经是满值**了。
    症状："第一拍整个是白的，后面才对"。写成 `exp(-abs(tl - t0) / k)`。

23. **halation / bloom 的阈值必须高于底板自身的亮度。**
    浅底片（相纸 0.97 量级）上把阈值定成 0.80，**纸自己就够格当"高光"**，
    整帧泛成三文鱼色，看着像"调色不对"。暗场用 0.72，纸面用 0.99
    ——纸面那条阈值只留给爆闪，纸本身就不该有任何光晕。

24. **`anim.out_expo` 饱和在 ~0.93，永远到不了 0.98。**
    拿 `if eased > 0.98:` 当"这段动画播完了"的门，**那段就从来没画出来过**，
    而且是静默的——没有报错、没有警告，只是画面上少了一组东西。
    完成判定要另给一个时钟（`out_expo((tl - t0) / d, 5.0)`），
    不要复用同一个缓动函数的返回值当两种用途。

25. **`_Pass` 每画一个图元都做一次全画幅 `getbbox()` 扫描。**
    在 2× 图层上一次扫描几毫秒，一帧画上百个 `path`（水场一帧 336 个）就是上千次，
    实测占一帧 **~25%**。把扫描收进图元自己的包围盒就能省掉，**画面一个像素都不变**
    ——比换显卡便宜得多。详见 `references/performance.md`。

26. **浅底片上"最深的黑"不是靠换墨色，是靠明暗窗口（纸号）。**
    同一张 3D 明暗图，只改映射窗口就能从"平的工作样片"变成"3 号纸的终片"。
    实测：不加窗口时终片最暗的 1% 只有 66、全画幅 40 以下**仅 7 个像素**（＝根本没有黑）；
    加上窗口（`lo=0.10, hi=0.80`）之后 1% 分位 21、40 以下 11740 px。
    一个 `density(cov, lum, floor, gamma, lo, hi)` 就能同时表达
    "潜影"（大 floor）、"工作样片"（窗口全开）和"终片"（窗口收紧）。

## 音频

27. **真峰必须在过采样之后压，不是整体乘一个系数。**
    采样峰值定 0.84 只保证"采样点"不超，编码器在**采样之间**照样顶上去。
    做法：4× 过采样（FFT 补零）→ 软限幅（tanh 做的膝）→ 回采样。
    实测能把波形真峰压到**与采样峰相等**（−2.5 dBTP），而**响度一点不掉**
    （仍 −13.6 LUFS）——因为压的是瞬态，主体被抬了回来。

28. **AAC 的默认码率可能直接把片子编爆。**
    `-b:a 256k`（ffmpeg 原生 aac）在**瞬态密集**的素材（底鼓 + 冲击 + 刷子）上，
    解码后采样峰值到 **1.0866（+0.72 dBFS）**：波形真峰才 −2.5 dBTP，编解码一趟涨 3.2 dB。
    各档实测（同一条波形，解码回来的真峰）：
    `256k +0.72（削波）` / `384k −2.20` / `512k −2.38` / `aac_mf 192k −2.26`。
    ⇒ **用 384k，并且渲染完必须把音频解码回来量真峰**，别只信波形文件的数。
    （本文档第 14 条记的"AAC 抬 0.3~1.0 dB"只是常见值，**上限不止**。）

## 文案

29. **屏幕上出现的数字，必须能对上代码。**
    技术栏写 `SAMPLES 260 000`，而实际采样是 1000 × 240 = **240 000**。
    全片唯一那处"关于画面本身的陈述"，正好就是对不上的那处。
    改采样网格时 `theme.py` 里的数字要跟着改；交片前拿代码核一遍。

# 第三批（2026-09-28，做第五种视觉语言「恒星 / 普朗克真彩色」时踩的）

第二支片子（KELVIN，一颗被算出来的恒星）跨了物理和渲染两边，踩的东西和前面不太一样。

35. **float32 下 `sin(π)` 是负数，幂运算直接出 NaN。**
    `np.sin(a) ** 0.78`——`a` 取到 π 时 `sin` 会给一个 **−1e−7 量级的小负数**，
    分数次幂把它变成 NaN，然后污染整条几何 / 整条粒子位置。
    别指望 `sin` 的取值范围：**只要底数可能为负就先 `np.clip(x, 0, None)`**。
    这类"偶尔炸一次"的 bug 在单帧预览里看不出来。

36. **加色光晕只能对称衰减。**
    `clip(-60)` 这种只给下界的写法，会在另一侧放开 `exp(+2.3) ≈ 10` 倍的加法光，
    一个画幅一次性糊掉。写成对称的 `exp(-|d| / k)`，或者两侧都给界。

37. **时间轴只能有一个来源。**
    `round()` 和 `int()` 截断在浮点上会差一个样本。音频按一个公式排、画面按另一个排，
    就会慢慢错开——而且是那种"看半天说不出哪里不对"的错开。

38. **概念和画面对不上时，改画面，不要改文案。**
    有一场名义上讲「颜色 = 温度」，却在展示一条彩虹——那是两回事。
    正确做法是重构成两层（上面黑体色温条、下面真实光谱带），让**画面本身**
    就是那条普朗克曲线，而不是在旁边补一行说明。文案解释不了画面自己的矛盾。

39. **文档里的命令要考虑平台。** 本机上 `python3` 是应用商店的别名桩，
    非交互下**静默退出（exit 49，什么都不吐）**，极容易被误判成脚本坏了。
    Windows 上把文中的 `python3` 换成 `py -3`。

> 第 29 条（屏幕上的数字必须与引擎实际值对账）在第二支里**又中了一次**：
> 技术栏的常量与引擎实际用的值不一样。这条不是偶发，是流程问题——
> **交片前拿代码把屏幕上的每个数字核一遍**。

第三支片子把交付规格从 720p30 提到 1080p60，踩的是"规格变了但耦合没跟着变"这一类。

40. **改帧率时，音频分析也得跟着改。**
    `A.analyse(st, sr)` 的默认是 `fps=30`；画面若是 900 帧（60 fps），
    出来的频谱只有 450 帧，频谱条只覆盖前一半，看着像"波形慢慢落后于画面"。
    改成 `A.analyse(st, sr, fps=T.FPS)`。症状像音乐对不上，真因是数组长度对不上。
    （默认交付是 30 fps / 450 帧，两边一致；只有被点名提帧率时才会踩到这条。）

41. **交付尺寸 ≠ 排版空间时：软的更软，锐的一样锐。**
    `Canvas(T.W, T.H, ss, out=(OUT_W, OUT_H))` 里矢量/文字通道按**交付尺寸**超采样
    （字是锐的），而场景在排版空间生成的软遮罩（辉光、颗粒、纸纹）入板时重采样一次。
    字号、边距按排版空间写就行；但**网点、点刻、拼贴这类细纹理必须把 `W, H` 设成交付尺寸**，
    否则交付尺寸上的纹理是重采样出来的。别在两种情况下用同一套网点 `cell`。

42. **`c.add` / `c.rgb` 现在是视图，不是裸 ndarray。**
    写法不用改（`+=`、`*=`、`np.clip`、`.mean(...)` 都通），它负责把排版空间尺寸的数组
    重采样到交付网格。但**别把它存起来跨帧复用**：它每次取都指向当前缓冲，
    缓冲被整块替换（`chroma`、`tonemap` 会这么做）之后，旧的引用就指向上一帧了。

43. **60 fps 下"按帧写死"的时长会缩水一半。**
    `if f > 6:` 在 30 fps 是 0.2 s，在 60 fps 变成 0.1 s。时间一律走 `t` / `tl`（秒），
    需要帧数就 `int(round(sec * T.FPS))`。同样的坑在 30→60 的迁移里会一次出现十几处。
